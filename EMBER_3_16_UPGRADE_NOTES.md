# Ember 3.16 Upgrade - Progress Notes

**Branch:** `ember-3.16-upgrade`  
**Date:** December 23, 2025  
**Status:** Work in Progress

## Problem Summary
Two persistent Ember runtime errors after attempting to upgrade to Ember 3.16:
1. `(0 , _emberBabel.arrayLikeToArray) is not a function` - Error at vendor.js:56927
2. `Cannot read properties of null (reading 'syscall')` - Error at vendor.js:59727 (AppendOpcodes.evaluate)

## Root Cause Analysis

### Error 1: arrayLikeToArray is not a function
**Cause:** Version mismatch between Ember runtime (3.13) and the @glimmer/compiler/Glimmer VM (compiled for 3.16).
- The template compiler code in @glimmer/compiler was trying to use `_emberBabel.arrayLikeToArray`
- Ember's ember-babel module didn't export this function (removed in later versions)
- The helper was expected to be available by @glimmer/compiler which was pre-compiled into vendor

**Solution Implemented:**
1. **Updated package.json** to Ember 3.16.0:
   - `ember-cli`: 3.13 → 3.16
   - `ember-data`: 3.13 → 3.16  
   - `ember-source`: 3.13 → 3.16
   - `ember-cli-babel`: 7.7.3 → 7.26.11
   - `ember-cli-htmlbars`: 3.0.1 → 4.0.0

2. **Created vendor/ember-babel-shim.js** with three-part strategy:
   - **Early Definition:** Defines `ember-babel` module with all helpers before vendor code runs
   - **Global Storage:** Stores helpers in `window.__emberBabelHelpers` for access
   - **Define Hook:** Intercepts `window.define()` to patch Ember's later ember-babel definition
     - When Ember's ember-babel is defined, our wrapper detects it's missing arrayLikeToArray
     - Wraps the factory function to inject missing helpers
     - Returns the patched module

3. **Added initializers/ember-babel-helpers.js** as runtime fallback:
   - Runs after boot to attach helpers to required module
   - Non-critical; main fix is in shim's define hook

### Error 2: Cannot read properties of null (reading 'syscall')
**Cause:** TBD - Glimmer VM opcode mismatch or missing opcode registration  
**Status:** Unresolved - requires further investigation

## Technical Details

### How the Shim Works
```
1. Shim runs first (prepended early in vendor.js)
   ↓
2. Stores helpers in window.__emberBabelHelpers
   ↓
3. Replaces window.define with wrapper function
   ↓
4. Later, Ember's ember-babel is defined
   ↓
5. Our define wrapper intercepts the call
   ↓
6. Detects it's missing arrayLikeToArray (checks factory.toString())
   ↓
7. Wraps the factory to patch in missing helpers
   ↓
8. @glimmer/compiler code can now use the helpers
```

### AMD Module System
- Ember uses AMD (Asynchronous Module Definition) loader
- Modules are defined with: `define('module-name', ['dep1', 'dep2'], factoryFn)`
- Requires are resolved at define-time, binding parameters to closure variables
- Our shim hooks at the right point to inject helpers before code tries to use them
